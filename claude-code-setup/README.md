# Установка Claude Code на рабочий ПК (Windows)

Цель — получить Claude Code, работающий **локально на машине**, чтобы он мог
реально ставить и настраивать софт. Веб-версия (claude.ai/code) для этого не
годится: она работает в одноразовом Linux-контейнере в облаке и доступа к
вашему диску не имеет в принципе.

## Шаг 0. Проверка (обязательно)

Скачайте `preflight.ps1` из этого каталога и запустите. Скрипт ничего не
меняет — только читает систему и печатает отчёт.

```powershell
powershell -ExecutionPolicy Bypass -File .\preflight.ps1
```

Права администратора не нужны. Смотрите блок **«2. Кириллица в путях»** — он
решает, каким способом ставить дальше.

---

## Проблема с кириллицей: в чём она здесь

Дома проблема вылезла в диалоге выбора каталога установки. У Claude Code
такого диалога **нет вообще** — путь жёстко зафиксирован:

| Что | Куда |
|---|---|
| Исполняемый файл | `%USERPROFILE%\.local\bin\claude.exe` |
| Версии и данные | `%USERPROFILE%\.local\share\claude` |
| Настройки | `%USERPROFILE%\.claude\` и `%USERPROFILE%\.claude.json` |

Выбрать другой каталог нельзя. Значит, если профиль называется
`C:\Users\Александр`, кириллица попадёт в путь установки автоматически —
обойти её выбором «другой папки», как дома, не получится.

**Но:** на рабочих машинах профиль часто заводят латиницей (`C:\Users\ivanov`),
даже когда отображаемое имя русское. Шаг 0 покажет, какой случай ваш.

---

## Вариант A — профиль латиницей (проблемы нет)

Откройте PowerShell (не от администратора) и выполните:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Либо через winget, если он есть:

```powershell
winget install Anthropic.ClaudeCode
```

Разница: нативная установка обновляется в фоне сама, winget — нет
(нужен периодический `winget upgrade Anthropic.ClaudeCode`).

Рекомендуется дополнительно поставить [Git for Windows](https://git-scm.com/downloads/win) —
без него Claude Code выполняет команды через PowerShell вместо Bash.

---

## Вариант B — профиль с кириллицей

### B1. WSL 2 — рекомендуемый путь

Внутри WSL домашний каталог — `/home/<имя>`, гарантированно ASCII. Кириллица
в профиле Windows на него не влияет никак. Бонусом WSL 2 даёт поддержку
песочницы, которой на нативной Windows нет.

```powershell
wsl --install -d Ubuntu
```

Перезагрузка, затем **внутри терминала Ubuntu** (не в PowerShell):

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version
```

Учтите: файлы Windows видны из WSL как `/mnt/c/...`, и поиск по ним работает
медленно и неполно. Проекты лучше держать в `/home/`.

### B2. Короткое имя 8.3 — запасной вариант

Если WSL на рабочей машине запрещён политикой. Шаг 0 покажет короткое имя
профиля (вида `C:\Users\ALEKSA~1`). Если оно доступно, задайте `HOME` на него
и ставьте нативно:

```powershell
$fso   = New-Object -ComObject Scripting.FileSystemObject
$short = $fso.GetFolder($env:USERPROFILE).ShortPath
setx HOME $short
```

Затем **закройте и откройте терминал заново** (`setx` действует только на
новые процессы) и установите:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Если preflight написал, что 8.3-имена недоступны, этот вариант не сработает —
генерация коротких имён отключена в системе. Остаётся WSL.

### B3. Переименование профиля — не делайте

Переименовать `C:\Users\Александр` штатными средствами нельзя: путь прописан
в реестре и в путях сотен приложений. На рабочей машине это прямая дорога к
сломанному профилю. Правильное решение на этом уровне — новая учётная запись
с латинским именем, и это вопрос к вашей ИТ-политике, а не к установщику.

## Кодировка консоли

Отдельная от путей проблема: консоль Windows по умолчанию в кодовой странице
866 или 1251, а Claude Code выводит UTF-8. Русский текст будет кракозябрами.

Лучшее решение — Windows Terminal (в Windows 11 стоит по умолчанию):

```powershell
winget install Microsoft.WindowsTerminal
```

Разовый обход в текущей сессии: `chcp 65001`.

---

## Шаг 1. Проверка установки

```powershell
claude --version     # должно напечатать версию, например 2.1.211 (Claude Code)
claude doctor        # диагностика установки и настроек
```

## Шаг 2. Вход

```powershell
claude
```

Откроется браузер для входа. Нужна подписка Pro, Max, Team, Enterprise или
аккаунт Console — бесплатный план Claude.ai доступа к Claude Code не даёт.

---

## Корпоративный прокси

Если preflight показал, что `claude.ai` или `downloads.claude.ai` недоступны
по 443 — это фильтрация трафика, а не поломка установщика. Понадобится либо
доступ к этим доменам, либо настройка прокси через переменные окружения
`HTTPS_PROXY` / `HTTP_PROXY`. Требования к сети описаны в
[документации](https://code.claude.com/docs/en/network-config).

---

## Что дальше

После установки открываете терминал в нужном каталоге, запускаете `claude` —
и с этого момента он работает прямо на машине: видит диск, ставит программы,
правит конфиги. Тогда и вернёмся к Hermes Desktop, уже с реальным доступом.
